# Flooded Area Mapping from Sentinel-1 Satellite Images

**Project:** Pixel-level water-area mapping with CNNs  
**Dataset:** Sen1Floods11 v1.1 (hand-labelled Sentinel-1 SAR imagery)  
**Notebook:** `Flood_Mapping_Sen1Floods11(1).ipynb`  
**Environment:** Google Colab with a GPU recommended

This project compares three methods for identifying water pixels in Sentinel-1 Synthetic Aperture Radar (SAR) image chips:

1. **VH threshold baseline** — predicts water from a low normalized VH backscatter value. The threshold is selected using the validation set.
2. **Compact U-Net** — a U-Net segmentation model with a ResNet18 encoder trained from scratch.
3. **Transfer-learning U-Net** — a U-Net using an ImageNet-pretrained ResNet18 encoder, adapted to two-band SAR input.

The task is **binary pixel-level segmentation**: each valid pixel is predicted as water or non-water.

> **Important interpretation:** Sen1Floods11 hand-labelled masks mark water and non-water; they do not reliably separate newly flooded land from permanent water. This project should therefore be described as *water-area mapping* or *flood-inundation proxy mapping*, not definitive detection of newly flooded areas.

## Dataset

The project uses the public [Sen1Floods11 dataset](https://github.com/cloudtostreet/Sen1Floods11).

- The notebook downloads **446 hand-labelled 512 × 512 chips** and the official split CSV files from public Google Cloud Storage.
- Each input image uses two Sentinel-1 SAR bands: **VV** and **VH**. These are SAR measurements, not RGB image channels.
- Mask labels:
  - `0` = non-water
  - `1` = water
  - `-1` = invalid / ignored pixel
- Images are clipped and normalized, then resized for model input.
- Masks use nearest-neighbour resizing so their class IDs remain valid.
- Training-only flips and 90-degree rotations augment the data.
- Official training, validation, and test partitions are used. The VH threshold and best model checkpoints are selected with validation data; the test split is used for final evaluation.

The dataset is downloaded when the notebook runs, so the runtime needs internet access. No personal cloud API key is required by the notebook's anonymous public-bucket download.

## How the code works

The notebook is organized into these stages:

1. **Install and import libraries** — prepare image processing, deep learning, metrics, and plotting packages.
2. **Configure the experiment** — set the random seed, device, image size, batch size, epochs, learning rate, and output folder.
3. **Download the dataset** — retrieve hand-labelled Sentinel-1 images, masks, and official split CSV files.
4. **Pair chips and masks** — match each SAR image with its label mask and load train, validation, and test splits.
5. **Preprocess and augment** — normalize VV/VH values, resize images and masks, apply training-only augmentation, and count label pixels.
6. **Visualize samples** — display the VV band, VH band, and corresponding ground-truth water mask.
7. **Build and train models** — train the compact U-Net and transfer-learning U-Net, saving the checkpoint with the best validation IoU.
8. **Tune the baseline** — select a low-VH threshold using validation data only.
9. **Evaluate on the test set** — calculate pixel-level metrics, confusion matrices, and classification reports for all three methods.
10. **Inspect predictions** — save comparison figures showing SAR input, ground truth, and model predictions.
11. **Export results** — save CSV files, plots, text reports, model weights, run metadata, and a ZIP archive.

**How to interpret the log:**

- **Train loss:** measures error on the training data; lower is generally better.
- **Validation loss:** measures error on data not used to update model weights.
- **Validation IoU:** measures overlap between predicted water pixels and labelled water pixels. Higher is better.
- **Validation Dice:** another overlap score, also called F1 for binary segmentation. Higher is better.

The first epoch's low IoU followed by improvement in later epochs shows that the model began learning useful water/non-water patterns. Validation scores may fluctuate, so the notebook saves the checkpoint with the best validation IoU rather than automatically treating the final epoch as best.

**Explanation:** The selected threshold for this run was `0.525`, with validation IoU approximately `0.5112`. This threshold is then evaluated on the held-out test split. This method is a simple SAR backscatter baseline, not NDWI; NDWI requires optical bands.

**How to interpret these results:**

- **Precision:** of the pixels predicted as water, how many are actually labelled water.

For the **water class**, the transfer-learning U-Net has the highest F1/Dice in this recorded run (`0.782935`) and the highest recall (`0.804739`). The compact U-Net has the highest water precision in this run. These trade-offs matter: higher recall can come with more false-positive water predictions.

The non-water class scores are high for all three approaches, but overall accuracy alone can be misleading when the classes are imbalanced. Review water IoU/Dice, precision, recall, confusion matrices, and prediction overlays together.

## Understanding the output

### Confusion matrix

The notebook saves one pixel-level confusion matrix per approach. Read the matrix as actual labels on rows and predictions on columns:

| | Predicted non-water | Predicted water |
|---|---|---|
| **Actual non-water** | True negative (TN) | False positive (FP) |
| **Actual water** | False negative (FN) | True positive (TP) |

- **True positive:** a labelled water pixel correctly predicted as water.
- **True negative:** a labelled non-water pixel correctly predicted as non-water.
- **False positive:** a non-water pixel incorrectly predicted as water; this can overestimate water extent.
- **False negative:** a water pixel incorrectly predicted as non-water; this can miss water extent.

More correct predictions on the diagonal and fewer errors off the diagonal are generally desirable.

### Loss and metric curves

The `*_curves.png` plots show training and validation behaviour over epochs. Training loss should generally decrease. If training loss continues decreasing while validation loss rises, the model may be overfitting. Validation IoU and Dice help show whether water-mask overlap improves.

### Prediction overlays

The saved overlay images compare the SAR input, hand-labelled mask, and predictions from the baseline and both U-Net models. Use them to discuss where a model misses labelled water or incorrectly labels non-water as water.

## Troubleshooting

- **GPU runtime remains queued:** wait and retry later, or choose CPU if available. Training on CPU can be much slower.
- **Dataset download fails:** check internet access and rerun the download cell.
- **CUDA out-of-memory:** lower the batch size in the configuration cell (for example, from 8 to 4), then rerun the relevant cells.
- **Missing package:** rerun the installation cell and restart the runtime if necessary.
- **No output files:** check that training, evaluation, and export cells completed and inspect the printed output directory.
- **Runtime reset:** rerun the notebook from the beginning so that variables, downloaded data, and model weights are restored.

## Limitations

- The masks represent water/non-water and cannot reliably distinguish permanent water from newly flooded areas.
- The official split is chip-level; spatial proximity between chips may affect how well results transfer to new locations.
- Invalid mask values (`-1`) are excluded from training loss and evaluation.
- Water and non-water are imbalanced, so accuracy should not be interpreted alone.
- Results can vary with hardware, dependency versions, data access, and training randomness.
- Use the held-out test split for final evaluation; do not tune thresholds or hyperparameters against test metrics.
